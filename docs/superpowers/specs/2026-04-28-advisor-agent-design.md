# Governance Advisor Agent

**Date:** 2026-04-28  
**Status:** Approved  
**Scope:** LLM-powered governance advisor with RAG over platform data, free-form Q&A, and AI-assisted workflow building. Built on LiteLLM + pgvector, defaulting to Ollama/qwen3.5:9b.

---

## Overview

The Advisor is a chat-based agent embedded in the IntelliGuard dashboard. It has two modes:

- **Chat mode** — free-form governance Q&A grounded in live platform data (audit events, policy decisions, workflow traces, agent identities, evaluation results) via RAG retrieval
- **Build mode** — natural language → workflow definition, with a preview card offering "Create directly" or "Open in Builder" actions

The advisor is always accessible via a floating panel (bottom-right), and surfaces contextually on the Workflow Trace and Audit Events views via "Ask about this" triggers.

## Data Model

### `advisor_documents`
Chunked, embedded source documents for RAG retrieval. Populated by `AdvisorIndexer` from existing platform tables.

| Column | Type | Notes |
|---|---|---|
| `doc_id` | String PK | |
| `source_type` | String | `audit_event` \| `policy_decision` \| `workflow_trace` \| `guardrail_policy` \| `agent_identity` \| `evaluation_result` |
| `source_id` | String | ID of the originating row |
| `content` | Text | Human-readable chunk for embedding |
| `embedding` | vector(768) | pgvector column — cosine similarity search. Dimension matches embed model (768 for nomic-embed-text; configurable via `ADVISOR_EMBED_DIMENSIONS`) |
| `metadata` | JSONB | `{agent_id, session_id, environment, created_at, ...}` |
| `indexed_at` | DateTime | Last time this doc was indexed |

### `advisor_conversations`
Chat session history per authenticated user.

| Column | Type | Notes |
|---|---|---|
| `conversation_id` | String PK | |
| `user_id` | String FK → `users` | |
| `environment` | String | Environment context for RAG filtering |
| `title` | String | Auto-generated from first message |
| `created_at` | DateTime | |
| `updated_at` | DateTime | |

### `advisor_messages`
Individual turns in a conversation.

| Column | Type | Notes |
|---|---|---|
| `message_id` | String PK | |
| `conversation_id` | String FK → `advisor_conversations` | |
| `role` | String | `user` \| `assistant` |
| `content` | Text | |
| `context_docs` | JSONB | Retrieved doc IDs + snippets used for this response |
| `mode` | String | `chat` \| `build` |
| `created_at` | DateTime | |

### `advisor_workflow_drafts`
Workflow definitions generated by the advisor, pending user action.

| Column | Type | Notes |
|---|---|---|
| `draft_id` | String PK | |
| `conversation_id` | String FK → `advisor_conversations` | |
| `message_id` | String FK → `advisor_messages` | |
| `workflow_definition` | JSONB | Full `WorkflowDefinition` payload, ready to POST to `/v1/workflow-marketplace` |
| `status` | String | `pending` \| `created` \| `discarded` |
| `created_workflow_id` | String nullable | Set if user clicked "Create directly" |
| `created_at` | DateTime | |

## Architecture

### Module layout

```
agent_governance/
  advisor/
    __init__.py
    gateway.py     # LLMGateway — LiteLLM wrapper
    rag.py         # AdvisorRAG — pgvector indexing + retrieval
    indexer.py     # AdvisorIndexer — syncs DB rows → advisor_documents
    chat.py        # AdvisorChat — Q&A handler
    builder.py     # AdvisorBuilder — workflow generation handler
    prompts.py     # system prompts for chat and build modes
```

### `LLMGateway` — `advisor/gateway.py`

Thin LiteLLM wrapper. All configuration via env vars:

```
ADVISOR_PROVIDER = "ollama"               # ollama | openai | anthropic
ADVISOR_MODEL    = "ollama/qwen3.5:9b"    # LiteLLM provider/model format
ADVISOR_BASE_URL = "http://localhost:11434"
ADVISOR_EMBED_MODEL = "ollama/nomic-embed-text"
```

Exposes:
- `complete(messages: list[dict]) → str`
- `stream(messages: list[dict]) → AsyncIterator[str]`
- `embed(text: str) → list[float]`

LiteLLM's `provider/model` convention means switching to OpenAI or Anthropic is a single env var change — no code modification required.

### `AdvisorRAG` — `advisor/rag.py`

Uses `pgvector` extension on the existing Postgres instance. No new infrastructure required.

- `index_document(source_type, source_id, content, metadata)` — chunk text, embed via `LLMGateway.embed`, upsert into `advisor_documents`
- `retrieve(query, environment, top_k=5) → list[Document]` — embed query, cosine similarity search on `advisor_documents` filtered by `metadata->>'environment'`

### `AdvisorIndexer` — `advisor/indexer.py`

Syncs existing platform data into `advisor_documents`. Runs on two triggers:

1. **Startup** — full sync of all rows not yet in `advisor_documents` (checked via `source_id` lookup)
2. **Post-run** — called at the end of `run_customer_support_agent` and `run_customer_support_workflow` to index the new session's events immediately

Indexed source types and their content format:

| Source | Content format |
|---|---|
| `audit_event` | `"{decision} on {tool_name} for agent {agent_id}: {reason} (risk: {risk_score})"` |
| `policy_decision` | `"Agent {agent_id} {decision} for {tool_name}: {reason}. Rules: {triggered_rules}"` |
| `workflow_trace` | `"Workflow {workflow_id} — {name}: {summary}. Status: {status}"` |
| `guardrail_policy` | `"Policy {display_name} ({environment}): {config summary}"` |
| `agent_identity` | `"Agent {display_name} ({agent_type}, {environment}): {purpose}. Tools: {tools}"` |
| `evaluation_result` | `"Evaluation of {agent_id} — {evaluator_type}: score {score}, passed={passed}. {findings}"` |

## API Endpoints

All endpoints require bearer auth. Environment context is passed in the request body and used for RAG filtering.

### Chat
```
POST /v1/advisor/chat
     body:     {conversation_id?, message, environment}
     response: {message_id, reply, sources: [{doc_id, snippet, source_type}], conversation_id}
```

### Build
```
POST /v1/advisor/build
     body:     {conversation_id?, message, environment}
     response: {message_id, reply, draft_id, workflow_definition, conversation_id}
```

### Draft actions
```
POST /v1/advisor/drafts/{draft_id}/create
     response: {workflow_definition_id}   # submits draft to /v1/workflow-marketplace

POST /v1/advisor/drafts/{draft_id}/open-in-builder
     response: {workflow_definition}      # returns JSON to pre-fill the builder form

POST /v1/advisor/drafts/{draft_id}/discard
     response: {ok: true}
```

### Conversation history
```
GET  /v1/advisor/conversations
     response: list[{conversation_id, title, environment, updated_at}]

GET  /v1/advisor/conversations/{id}/messages
     response: list[{message_id, role, content, mode, sources, created_at}]
```

## Runtime Flow

### Chat mode

```
User sends message
  → AdvisorRAG.retrieve(message, environment, top_k=5)
      → embed query (nomic-embed-text via Ollama)
      → cosine similarity search on advisor_documents (env-filtered)
      → return top 5 chunks + metadata

  → AdvisorChat.respond(message, retrieved_docs, conversation_history)
      → build prompt:
          system:  governance expert persona + platform capability description
          context: retrieved doc snippets (labelled by source_type)
          history: last 10 messages from conversation
          user:    message
      → LLMGateway.stream(messages)
      → persist advisor_messages (user + assistant turns)
      → return streamed reply + source doc references
```

Example questions answerable via RAG:
- "Why was the transaction analyst agent blocked yesterday?" → retrieves audit events
- "Which agents have no guardrail policy assigned?" → retrieves agent identities + assignments
- "What's the PII leakage score for the last 10 workflow runs?" → retrieves evaluation results
- "Show me policies with a block threshold below 70" → retrieves guardrail policies

### Build mode

Activated by prefixing the message with `/build` in the UI, or by calling `/v1/advisor/build` directly.

```
User sends build request
  e.g. "/build a workflow that verifies identity, checks fraud risk, then escalates high-risk cases"

  → AdvisorRAG.retrieve(message, environment, top_k=3)
      → retrieve similar existing workflow definitions + relevant agents

  → fetch live agent list + tool list from DB
      (always fresh — not from RAG — so generated JSON references real IDs)

  → AdvisorBuilder.generate(message, retrieved_docs, agents, tools)
      → build prompt:
          system:  WorkflowDefinition JSON schema + field descriptions + valid agent/tool IDs
          context: similar existing workflows (from RAG) + available agents + available tools
          user:    natural language request
      → LLMGateway.complete(messages)   # non-streaming — need full JSON output
      → parse + validate generated WorkflowDefinition JSON
          → verify lead_agent_id exists
          → verify each step's agent_id and tool_name exist
          → fill missing fields with sensible defaults
      → persist advisor_workflow_draft (status=pending)
      → persist advisor_messages
      → return draft_id + workflow_definition + natural language explanation
```

### Draft lifecycle

```
advisor_workflow_draft created (status=pending)
  → user clicks "Create directly"
      → POST /v1/advisor/drafts/{id}/create
      → submits workflow_definition to /v1/workflow-marketplace
      → draft.status = created, draft.created_workflow_id = new workflow_definition_id

  → user clicks "Open in Builder"
      → POST /v1/advisor/drafts/{id}/open-in-builder
      → returns workflow_definition JSON
      → frontend injects into workflowDefinitionJson state
      → navigates to Workflows → Builder tab
      → draft.status = discarded (user is editing it manually)

  → user ignores it
      → draft stays pending (no side effects)
```

## Environment & Dependencies

New Python dependencies:
```
litellm          # LLM gateway, multi-provider
pgvector         # SQLAlchemy pgvector integration
```

New env vars (all optional, defaults to local Ollama):
```
ADVISOR_PROVIDER      = "ollama"
ADVISOR_MODEL         = "ollama/qwen3.5:9b"
ADVISOR_BASE_URL      = "http://localhost:11434"
ADVISOR_EMBED_MODEL   = "ollama/nomic-embed-text"
ADVISOR_TOP_K         = "5"
ADVISOR_MAX_HISTORY   = "10"
ADVISOR_EMBED_DIMENSIONS = "768"   # 768 for nomic-embed-text; 1536 for OpenAI ada-002
```

Postgres requires `pgvector` extension enabled:
```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

This is handled automatically in `init_db()` on startup.

## Backwards Compatibility

- All advisor endpoints are new — no existing endpoints modified
- `advisor_documents` table is additive; indexing runs passively on startup
- If Ollama is unavailable, advisor endpoints return a graceful error; the rest of the platform is unaffected
- The floating chat panel is hidden if `ADVISOR_MODEL` env var is not set (opt-in)

## Out of Scope (future)

- LLM-powered evaluators (using the same LLMGateway)
- Advisor memory across sessions (persistent user preferences)
- Streaming workflow generation (build mode uses blocking complete() today)
- Advisor actions governed by the policy engine (Approach C from design)
- Analytics on advisor usage (which questions are asked most)
